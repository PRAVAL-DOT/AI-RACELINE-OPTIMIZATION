# F1 Ideal Lap Profile Generator

A research-grade telemetry analysis tool that builds an **ideal reference driving profile** from FastF1 qualifying data. Identifies the theoretical fastest lap by taking the 90th-percentile speed at every point on the track, detects all corners using official circuit data, and breaks down performance by sector.

This is **Phase 1** of a larger AI-based racing line optimisation and driver coaching system.

---

## What it does

- Loads qualifying telemetry for any F1 race weekend via [FastF1](https://github.com/theOehrly/Fast-F1)
- Selects the top 10% of laps as the elite reference pool
- Resamples all laps to a common **distance grid** (not time-based) at ~1.8m resolution
- Builds an **ideal speed/throttle/brake profile** using 90th-percentile aggregation
- Detects all corners using **official FastF1 circuit geometry** (not speed-threshold heuristics)
- Derives **exact sector split distances** from the fastest lap's telemetry timestamps
- Estimates ideal **sector and lap times** via kinematic integration (dt = ds/v)
- Renders a 4-panel dark-theme dashboard with corner markers, sector shading, and a reference time table

## Quickstart

### 1. Clone and install dependencies

```bash
git clone https://github.com/YOUR_USERNAME/AI-RACELINE-OPTIMIZATION.git
cd AI-RACELINE-OPTIMIZATION
pip install -r requirements.txt
```

### 2. Run with defaults (Bahrain 2025 Qualifying)

```bash
python main.py
```

### 3. Run for a different race

```bash
python main.py --year 2024 --gp Monza --session Q
python main.py --year 2023 --gp Silverstone --session R
```

### 4. All CLI options

| Flag | Default | Description |
|------|---------|-------------|
| `--year` | `2025` | Season year |
| `--gp` | `Bahrain` | Grand Prix name (FastF1 fuzzy matches) |
| `--session` | `Q` | Session type: `Q`, `R`, `FP1`, `FP2`, `FP3` |
| `--cache` | `cache` | Path to FastF1 cache directory |
| `--output` | `outputs/ideal_profile.png` | Output plot path |
| `--n-points` | `3000` | Distance grid resolution |

### 5. Run tests

```bash
pytest tests/ -v
```

## Key design decisions

### Distance-based alignment (not time-based)
Two laps at different times cannot be compared point-to-point on a time axis — a slow lap and a fast lap will be at completely different circuit positions at T=30s. All analysis is aligned to **metres from the start line** using FastF1's built-in `Distance` column (real metres, not XY-derived).

### Official corner detection
Previous versions used speed-threshold heuristics (`speed < percentile(30)`) which missed chicanes and flat-out corners. This version uses `session.get_circuit_info().corners` — the official corner distances from FastF1 — and expands each corner's entry/exit from that anchor point. This reliably produces the correct corner count for any circuit.

### 90th-percentile ideal profile
Rather than comparing against a single "fast" driver (which encodes their specific style), the ideal is the **envelope** of the fastest speed achieved at each track position across all elite laps. Any driver could theoretically achieve this — it's the theoretical optimum, not a copy of one driver's style.

## Roadmap

This project will evolve into a full **AI-based driver coaching system** with the following phases:

- **Phase 1** *(current)* — Ideal lap profile + corner detection
- **Phase 2** — Driver vs ideal comparison: per-corner time delta, braking point deviation, throttle application analysis
- **Phase 3** — Driver fingerprinting via metric learning: learn a compact latent representation of each driver's style that generalises across tracks (contrastive learning / SupCon loss)
- **Phase 4** — Style transfer: given a student driver's telemetry, generate what their lap would look like if they adopted the style of a reference driver
- **Phase 5** *(exploratory)* — Vision module: infer pseudo-telemetry from onboard video using optical flow and monocular depth

## Data source

All telemetry is sourced via [FastF1](https://github.com/theOehrly/Fast-F1) which accesses the official F1 timing API. Data is cached locally after the first download — a full qualifying session is typically ~50–150 MB.
